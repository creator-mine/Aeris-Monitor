Потоки данных

Внутри периферии: датчик в контроллер

  1. Сканирование шины

    При старте и по команде пересканирования реестр перебирает адреса I²C.

  2. Определение типа

    На каждый адрес вызывается detect() каждого драйвера.

  3. Клонирование и инициализация

    Реестр создаёт свежий экземпляр драйвера через clone().

  4. Опрос по расписанию

    Каждый драйвер сообщает свой интервал опроса.

От контроллера наружу

  1. MQTT

    Каждая метрика уходит отдельным сообщением в свой топик.

  2. REST и WebSocket

    Локально — REST и WebSocket с push-обновлениями.

  3. История на SD

    Каждое значение дописывается в дневной CSV-файл.

  4. Регистрация на сервере

    Контроллер повторяет регистрацию раз в 30 секунд.

Пара «драйвер + адрес + мультиплексор + канал».

🔀

Мультиплексоры

Список адресов TCA9548A из конфигурации.

🔒

Блокировка шины

Все обращения к шине проходят под семафором.

🔢

Счётчик compositionRevision растёт при каждом изменении состава датчиков.

Жизненный цикл модуля

Состояние Как обнаруживается Что видит пользователь
Отсутствует Нет ответа на адресе при сканировании Датчика нет в списке
Онлайн Успешный ответ на шине Обычные значения
Офлайн Проверка живости не получила ответа Запись остаётся, значения — «нет данных»
Восстановление Создаётся новый клон драйвера Метрики снова обновляются

Офлайн-записи не удаляются намеренно.

Модель данных

Значение метрики проходит через систему с тремя уровнями описания.

1

Тип датчика

Одно число плюс имя.

2

Экземпляр датчика

Строка вида BME680_0x76.

3

Метрика

Ключ, единица измерения и значение.

🔑

Ключи метрик могут совпадать у разных датчиков.
