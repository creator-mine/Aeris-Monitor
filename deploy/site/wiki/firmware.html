Прошивка и протокол

Как собрать и прошить обе прошивки.

Состав репозитория

firmware/
├── main_controller/        прошивка главного контроллера
│   ├── include/            config.h, uart_protocol.h, web_server.h, ota_updater.h
│   ├── src/                main.cpp и остальные модули
│   └── platformio.ini      среды esp32-c3, esp32-c6 и esp32-s3
├── sensor_module/          прошивка сенсорного модуля
│   ├── include/            config.h, uart_protocol.h
│   ├── src/main.cpp
│   └── platformio.ini      среда esp32-c6 (модуль)
├── shared/

├── test_simple/            минимальный проверочный проект

Сборка прошивок

Сборка идёт через PlatformIO, прошивок две.

Установите PlatformIO Core

pipx install platformio
# либо
pip install -U platformio

Соберите главный контроллер

cd firmware/main_controller
pio run -e esp32-c3

Для платы ESP32-S3 — среда esp32-s3.

Для ESP32-C6 — среда esp32-c6 (контроллер, 16 МБ).

Соберите сенсорный модуль

cd firmware/sensor_module
pio run -e esp32-c6

Та же плата C6, но прошивка модуля.

Прошейте платы

# контроллер
cd firmware/main_controller
pio run -e esp32-c3 -t upload
pio run -e esp32-c6 -t upload

# сенсорный модуль
cd ../sensor_module
pio run -e esp32-c6 -t upload

Скорость загрузки поднята до 921600 бод.

Цель сборки Плата Занято flash Занято RAM
esp32-c3 lolin_c3_mini около 71 % около 23 %
esp32-c6 (контроллер) esp32-c6-devkitc-1 около 21 % около 25 %
esp32-c6 (модуль) esp32-c6-devkitc-1 около 27 % около 5 %
esp32-s3 esp32-s3-devkitc-1 около 20 % около 26 %
📏

У C3 флеш заполнен примерно на 71 %.

Первичная прошивка и настройка

  1. Включите контроллер

    Контроллер поднимает точку доступа Aeris-Setup-XXXX.

  2. Откройте страницу настройки

    Откройте http://192.168.4.1.

  3. Дождитесь перезагрузки

    Все действия видны в Serial на 115200.

  4. Подключите модуль

    Соедините TX и RX перекрёстно.

  5. Проверьте регистрацию

    Проверьте регистрацию в Serial.

🔑

Точка доступа живёт пять минут.

Обновление по воздуху

У каждой платы свой бинарник и свой манифест.

Тип устройства Бинарник Манифест версии
esp32c3 /fw/main.bin /fw/version.json
esp32s3 /fw/main_esp32-s3.bin /fw/version-esp32-s3.json
esp32c6 /fw/main_esp32-c6.bin /fw/version-esp32-c6.json
  1. Контроллер спрашивает манифест

    По HTTPS запрашивается файл версии.

  2. Качает новый образ

    Бинарник пишется в свободный OTA-слот.

  3. Перезагружается и проверяет себя

    Новая прошивка должна отдать признак успешного старта.

  4. Откат по команде

    Возврат доступен как команда.

UART-протокол

Бинарный протокол с CRC-16.

Формат кадра

[0] HDR1 = 0xAA
[1] HDR2 = 0x55
[2] module_id
[3] cmd
[4] length_hi    ┐ длина полезной нагрузки,
[5] length_lo    ┘ 16 бит, старший байт первым
[6..] payload    длина байт
[6+len] crc_hi    ┐ CRC-16/CCITT,
[6+len+1] crc_lo  ┘ старший байт первым

Шесть байт заголовка, полезная нагрузка и два байта CRC.

Команды

Код Имя Кто шлёт Смысл
0x01 CMD_REGISTER модуль → контроллер Объявление типа и метрик
0x02 CMD_READ_SENSOR контроллер → модуль Запросить показания сейчас
0x03 CMD_SENSOR_DATA модуль → контроллер Значения метрик
0x04 CMD_HEARTBEAT обе стороны Признак жизни
0x05 CMD_CONFIG_UPDATE контроллер → модуль Модуль перерегистрируется
0x06 CMD_ACK обе стороны Подтверждение
0x07 CMD_NACK обе стороны Отказ

Полезная нагрузка регистрации

[sensor_count 1 байт]
для каждого датчика:
    [type_id 1 байт]
    [name_len 1 байт] [имя...]
    [metric_count 1 байт]
    для каждой метрики:
        [key_len 1 байт]  [ключ...]
        [unit_len 1 байт] [единица...]

Полезная нагрузка данных

[timestamp 4 байта]
[value_1 4 байта float]
[value_2 4 байта float]
[value_n 4 байта float]
📏

Порядок значений соответствует порядку регистрации.

CRC-16 и целостность кадра

CRC-16/CCITT, полином 0x1021, старт 0xFFFF.

uint16_t crc = 0xFFFF;
for (каждый байт заголовка и полезной нагрузки) {
    crc ^= (байт << 8);
    for (8 раз) {
        crc = (crc & 0x8000) ? ((crc << 1) ^ 0x1021) : (crc << 1);
    }
}

Приём разбирает поток побайтно.

Повреждённый кадр

Кадр с неверной суммой отбрасывается целиком.

Слишком длинное объявление

Длина объявляется в заголовке.

Поток регистрации

Модуль запускается

Поднимается шина и запускаются драйверы.

Сканируется шина

Реестр перебирает адреса и клонирует драйверы.

Формируется объявление

Кадр регистрации: тип, имя, метрики.

Контроллер строит карту метрик

Контроллер знает порядок и единицы метрик.

Идёт обмен значениями

Модуль шлёт кадры, контроллер публикует их.

🔄

Если состав датчиков изменился, регистрация повторяется.
